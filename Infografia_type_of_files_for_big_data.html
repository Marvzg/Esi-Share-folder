CSV & XML

Dos formatos que sostienen buena parte del intercambio de datos: uno tabular y minimalista, otro jerárquico y autodescriptivo. Comprender su estructura, usos y límites permite elegir el formato correcto en cada etapa de un pipeline de Big Data y web scraping.

.csv

Comma-Separated Values

Datos tabulares en texto plano, una fila por registro

Definición

Formato de texto plano que organiza datos en filas y columnas separadas por comas o delimitadores alternativos. Cada fila es un registro y cada columna un campo.

Nivel de estructura

Estructurado

Esquema implícito en la fila de encabezados. Estructura tabular predecible.

Usos en Big Data / Web Scraping

  • Exportación e importación de datos entre sistemas
  • Distribución de datasets públicos (Kaggle, datos abiertos)
  • Entrada a herramientas de BI (Power BI, Tableau)
  • Resultados de scraping: tablas de precios y listados

Ventajas

  • Universalmente legible en cualquier editor
  • Bajo overhead y fácil de generar o parsear
  • Compatible con toda herramienta de análisis
  • Sin dependencias externas

Limitaciones

  • Sin tipo de dato nativo: todo es texto
  • Delimitadores en valores requieren escape
  • No comprimido: ineficiente en gran volumen
  • Encoding variable (UTF-8, Latin-1) genera errores

Ejemplo con Python

Tras un scraping, los datos (producto, precio, disponibilidad) se guardan en una lista de diccionarios. pandas los convierte en un DataFrame y exporta con df.to_csv(). Otro script los lee con pd.read_csv(), limpia nulos y outliers, y envía el resultado a Power BI o a una base SQL.

.xml

eXtensible Markup Language

Datos jerárquicos con etiquetas anidadas y autodescriptivas

Definición

Lenguaje de marcado que estructura datos mediante etiquetas jerárquicas anidadas y autodescriptivas. Separa el contenido de su presentación y admite validación por esquema.

Nivel de estructura

Semi-estructurado

Jerarquía de nodos con esquema opcional (DTD, XSD) que permite validar la estructura.

Usos en Big Data / Web Scraping

  • Feeds RSS / Atom de noticias y contenidos
  • Web services SOAP e intercambio entre sistemas
  • Sitemaps para SEO y facturación electrónica
  • Configuración de aplicaciones y sistemas legacy

Ventajas

  • Autodescriptivo y jerárquico por diseño
  • Validación estricta con XSD / DTD
  • Independiente de plataforma; soporta namespaces
  • Amplio soporte en entornos empresariales

Limitaciones

  • Verboso: mucho overhead de etiquetas
  • Archivos más grandes que su equivalente JSON
  • Parsing más lento y con mayor uso de memoria
  • Sintaxis redundante y menos legible

Ejemplo con Python

Un script usa xml.etree.ElementTree o lxml para parsear un feed RSS de noticias. Recorre el árbol de nodos, extrae título, fecha y enlace de cada <item> y los guarda para análisis. Con lxml se usan consultas XPath para navegar directamente a nodos específicos.
